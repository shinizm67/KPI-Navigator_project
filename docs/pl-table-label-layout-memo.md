### 科目行の共通 UX

- **デフォルト行**: 飲食向け定番を事前配置
- **鉛筆アイコン**: ラベル **編集可能**（店舗ごとに名称・固定/変動の扱いが違うため）
- **＋ボタン**: 固定費・変動費それぞれで **ユーザーが行を追加**
- **−ボタン（行の削除）**: **物理削除しない** — 下記「行の非表示（ソフト削除）」参照

### 行の非表示（ソフト削除）— ChatGPT メモ合意・確定方針

**行をストレージから消さない。** 過去月の PL / Monthly 実績は `lineId` で紐づいているため、物理削除すると履歴・デバッグ・再表示が壊れる。

| 観点 | 方針 |
|------|------|
| ユーザー操作 | 「行を削除」＝ **非表示化**（目にうるさい行を画面から消す） |
| データ | `lineId` と過去の月次・日次値は **残す** |
| UI | `active: false`（または `hidden: true`）の行は **PL・Monthly とも描画しない** |
| 再表示 | v1.1 以降で「非表示の行を戻す」UIを検討可（データは最初から存在） |
| テンプレ変更 | テンプレから外れた `lineId` も同様に **非表示退避**（§ テンプレ変更時） |

**カタログ行の想定フィールド（追記）**

```ts
{
  lineId: string;
  labelJa: string;
  labelEn: string;
  bucket: 'fixed' | 'variable';
  inputMethod: 'daily-aggregate' | 'monthly-manual' | 'daily-aggregate-adjustment';
  active: boolean;        // false = 非表示（ソフト削除）
  sortOrder: number;
  editable: boolean;
  isDefault: boolean;
}
```

**実装メモ**: 集計・CSV・年次比較は `active` に関わらず **履歴データを参照可能**にしておく（管理画面や将来の「非表示行を含めて表示」用）。

## 参考予算（定規）— 変動費・費目別の目安

### 背景・目的

- 固定費は **売上に比例しない**（家賃・社員人件費など）。売上が落ちた月は **固定費率だけが上がる**。
- 「変動費率 ○○% が適正」という一般論は、**固定費が想定どおりの月**を暗黙にしている。
- **今月の KPI 予想売上** と **過去の自分の店の支出パターン** を掛け合わせ、
  - 変動費全体の **参考枠**
  - 費目別（食材・アルバイト等）の **定規（参考予算）**
  を示すことで、「この売上に対して変動費を使いすぎかも」が **数字で体に入る** UI を目指す。
- 表示は **トライアンドエラー的な振り返り** と **今後の対応** のヒント。断定の「適正値」ではない。

### 2 層構造

| 層 | 内容 | 主な入力 |
|----|------|----------|
| **L1 — 変動費全体の参考枠** | 固定費の食い込みを踏まえた「今月使える変動費の上限（目安）」 | KPI 月次予想売上、固定費実績 or 想定、目標総費率 |
| **L2 — 費目別定規** | 食材・アルバイト等、**行（`lineId`）ごとの参考金額** | L1 の母数 × 過去統計から得た **費目別比率** |

L1 で **枠**、L2 で **内訳の定規**。両方あると「全体オーバー」か「特定費目オーバー」かが切り分けやすい。

---

### L1 — 変動費全体の参考枠（固定費の食い込み）

#### 考え方

ある月、固定費が想定より売上を多く占めた場合、**同じ売上でも変動費に回せる余地は狭くなる**。

例（概念）:

- 目標 **総費率**（売上に対する支出全体）: 65%（店舗設定 or 業態テンプレの参考帯）
- 今月の **固定費率（実績）**: 37%（家賃・社員等。売上低下で率が上がった）
- → **変動費の参考上限率** ≒ 65% − 37% = **28%**
- → **変動費参考額** = KPI 月次予想売上 × 28%

「固定費に関してはだいたい 37% になった → 変動費は **これくらいが妥当だったかも**」という **残り枠** の見せ方。

#### 計算式（案）

```
変動費参考率 = clamp( 目標総費率 − 固定費率(実績 or 予想), 0, 1 )
変動費参考額 = KPI月次予想売上 × 変動費参考率
```

- **目標総費率**: ユーザー設定 > 業態テンプレデフォルト > （将来）過去実績の中央値
- **固定費率**: 当該月の PL 固定費合計 ÷ 売上（実績月）または ÷ **予想売上**（未来月・入力前）
- ラベルは **「適正」ではなく「参考枠」「今月の変動費の目安」**

#### UI 配置（案）

- KPI 帯の下、利益行の上、または KPI 帯内の **1 行サマリー**
- 表示例（JA）: `変動費の参考枠（固定費 37% 反映）｜¥1,400,000｜28.0%`

---

### L2 — 費目別定規（過去統計 × KPI 予想売上）

#### 考え方

過去の **変動費明細**（PL 月次 or Monthly Edit 日次集計）から、**費目（`lineId`）ごとに売上に対する比率** を統計化する。  
その比率を **今月の KPI 月次予想売上** に掛け、行ごとの **参考予算** とする。

```
費目参考予算 = KPI月次予想売上 × 費目参考比率(lineId)
```

例:

- 過去の「4月」で `food_purchase`（食材仕入）が売上の **28%** 前後だった
- 今月4月の KPI 予想売上 **500万** → 食材の定規 **約 140万**
- 同様に `labor_pt`（アルバイト）→ **何人分・何時間分** の目安として解釈可能（`docs/part-time-labor-cost.md` と将来連携）

#### 比率の統計 — 同月・同曜日（推奨）

飲食では **季節（同月）** と **週末 vs 平日（同曜日）** の両方が効く。

| 優先 | 集計キー | 用途 |
|------|----------|------|
| **1** | **同月 × 同曜日** | 例: 過去3年分の「4月の土曜」の `food_purchase / sales` |
| **2（フォールバック）** | **同月のみ** | 同月・同曜日のサンプルが少ない（年4〜5日）場合 |
| **3（フォールバック）** | **直近 N ヶ月・同曜日** | 新規店・データ不足時 |

**比率の集約方法（案）**

- デフォルト: **中央値**（繁忙月の外れ値に引っ張られにくい）
- オプション: **売上加重平均**（売上規模の大きい日を重視）

**1 データポイントの定義**

- 日次: `その日の費目支出 ÷ その日の売上`（Monthly Edit 日次明細 + 日次売上）
- 月次のみの場合: `その月の費目支出 ÷ その月の売上`（曜日分解不可 → Phase 1 はこちら）

#### L1 との接続（按分）

L2 を単独で足し合わせると L1 の枠を超えることがある。実装方針（要選択）:

| 方式 | 説明 |
|------|------|
| **A — 独立表示** | 各費目は過去比率 × 予想売上のみ。L1 は **全体チェック用** として別表示 |
| **B — 枠内按分** | L1 の変動費参考額を、L2 の **比率の相対配分** で按分し直す（合計が枠に収まる） |

v1 実装: **A（独立表示）採用**。ユーザーが「全体枠」と「費目定規」を両方見て調整。目安はコーナーの +/- トグルで一括表示（既定 OFF、無駄な常時線を出さない・行高拡張型）。B は設定で ON にできるとよい。

| `kpiNavigator.plTargetCostRate` | 目標総費率（0〜1）。未設定時はテンプレデフォルト |
| `kpiNavigator.plReferenceStats` | キャッシュ: `{ lineId, month, dow?, ratioMedian, sampleCount, computedAt }[]` |
| （既存） | `kpi-pl-expenses-v1:{year}` — 実績側 |

### 注意・制約

1. **固定/変動の線引き** は店舗差・編集でブレる → 比率もブレる。PL マスタの `bucket` を正とする。
2. **売上と支出のタイミング**（仕入翌月計上等）は v1 では **発生月ベース** で統一。
3. **外れ値月**（改装・コロナ等）は将来 **除外タグ** を検討。
4. **新規店** はサンプル不足 → 「データが溜まるまで参考表示なし」or 業態テンプレのみ。
5. **世間一般の固定費率・変動費率** は **比較用レンジ** に留め、L2 の主ロジックにはしない。

## 目的

- Pro の **PL（損益）表**で、Excel 原本と同様に **大見出し＋中見出し（小見出し）** を必ず持つ。
- 収入ブロックと支出ブロックを視覚的に分離しつつ、**ラベル列の横幅を食い過ぎない**。
- 科目名（家賃◉、★仕入 など）が長い行は **横書きのまま** 読める幅を確保する。

## 階層の定義（用語）

| 用語 | 例（JA） | 役割 |
|------|----------|------|
| **大見出し** | 支出、収入、店舗売上 | ブロック単位。縦書き1列で表現 |
| **中見出し** | 固定費、変動費、（セクション内のまとめ） | 横書き。B列。字太め・背景で区別 |
| **行ラベル（明細）** | 家賃◉、売上A、フード売上 | 横書き。B列。中見出しより一段細いスタイル |

**支出**の下に **固定費 / 変動費** の2中見出しがあり、各明細行がどちらかに属する（PDF・Excel 原本どおり）。

---

## 採用方針: ラベル2列（A＝大・縦 / B＝中＋明細・横）

### 列構成

| 列 | 幅（目安） | 内容 |
|----|------------|------|
| **A** | 28〜40px | 大見出しのみ。**縦書き**（`writing-mode: vertical-rl`）。同一ブロックは `rowspan` |
| **B** | 160〜220px | 中見出し行 ＋ 明細行（横書き） |
| **以降** | 既存どおり | 各月「金額｜％」×12 ＋ 年間 |

A+B を **まとめて左 sticky**（合計 200〜260px 前後）。横スクロールは月列のみ。

### 大見出しを縦書きにする理由

- 補足・ブロック名の説明に **1行分の幅** で済む（ユーザー案）。
- 慣れれば可読性は十分、という前提で **Pro の業務画面**向け。
- 長い科目名は B 列に集約でき、**1列に大+中+明細を連結**するより幅効率が良い。

### 英語（EN）フォールバック

- `Expenses` / `Income` / `Store sales` などは短いため、次のいずれか（実装時に選択）:
  - **同じ縦書き**（JP/EN 同一構造）
  - **A列は横書き・10px・最大2行**（`word-break`）
- ホバー／`title` で横書きフル表記（アクセシビリティ兼用）。

---

## ブロック別の置き方

### 収入（v1 飲食 — 大費目のみ）

v1 では **売上A/B/店舗売上内訳は置かない**（§ v1 飲食店テンプレ参照）。  
**総収入** と **総支出** の2行＋ KPI 帯＋ **利益（常時表示）**。

### 支出

```
A(縦: 支出 rowspan)     | B: 固定費（中見出し行・集計）
                        | B: 家賃◉ …（明細・固定費配下）
                        | B: 変動費（中見出し行・集計）
                        | B: ★仕入（食材）◉ …（明細・変動費配下）
```

- **固定費 / 変動費** は必ず **中見出し行** として出す（現行モックのようにいきなり数値行だけにしない）。

### 総収入・総支出・KPI（例外）

| 行 | ラベル列の扱い |
|----|----------------|
| **総収入** | B列に横書きラベル1本（太字）。A列は空または収入ブロック `rowspan` の続き |
| **総支出** | **A列＝「総支出」縦 or 横1本**。原価率・労働分配率・FL率は **B列に並べない** → **thead の第2行** または **1行だけのサブヘッダー**（金額｜％列と揃える） |
| 粗利益率・営業日数 等 | B列ラベル ＋ 既存 KPI 行スタイル |

「大見出しの右に小見出し×3」は **ラベル2列の問題ではなく、ヘッダー行設計** で吸収する（`PL表例4.pdf` の1月版参照）。

## 業態テンプレートとラベルの正（PL 親 → Monthly Edit 子）

### 方針（2026-06-04 合意）

- **PL 表がラベル定義のマスター（親）**。Monthly Edit の支出欄は **同じカタログを参照する子**。
- **PL ページ上部**（タイトル付近）に **業態テンプレート選択**（ドロップダウン等）を置き、選択でテンプレが切り替わる。
- 切り替えに伴い **PL の行ラベル・KPI 名** と **Monthly Edit の固定費／変動費の行ラベル** が連動して変わる。

現状は PL（`build_pl_table_page.py` の `EXPENSE_ROWS`）と Monthly Edit（`fixedItems` / `variableItems` の初期値）が **別々にハードコード** されているため、本方針で **1 つのテンプレ JSON** に統合する。

### テンプレートパック（初期案）

| ID | 想定業態 | KPI 例 | 備考 |
|----|----------|--------|------|
| `fnb` | 飲食 | 食材原価率、FL率、フード／ドリンク分割 | ローンチ正。`PL表例4.pdf` ベース |
| `retail` | 衣料・小売 | **仕入原価率**、人件費率（FL 表記は避ける or ML 等） | 支出費目は ★仕入系中心 |
| `service` | サロン・ジム等 | 材料・仕入原価率、外注費 | 対面サービス向け費目セット |

飲食以外は **表構造はほぼ共通**、差分は主に **支出費目リスト ＋ KPI サブヘッダー名 ＋（任意）収入 A/B のデフォルト名**。

### 永続化

| キー（案） | 内容 |
|------------|------|
| `kpiNavigator.plTemplateId` | `'fnb' \| 'retail' \| 'service'`（`localStorage` / 将来 API） |
| `kpiNavigator.plLineCatalog` | テンプレ適用後の行定義スナップショット（`lineId` 固定・表示ラベルのみ業態で変化） |

**`lineId`**（例: `rent`, `food_purchase`）は業態をまたいで不変。**表示ラベル**（JA/EN）だけテンプレで差し替える。集計・Monthly↔PL 連携は `lineId` で突合。

### UI 配置

- **選択 UI**: `app/profit/pl/index.html` 上部（年次ラベル・店舗名付近）。Pro のみ。
- Register 初回でも同じ ID を選ばせてもよいが、**運用上の変更は PL 上のドロップダウンが正** でもよい（1 画面に集約）。

### テンプレ変更時の注意

既に支出額を入力済みの場合:

1. **同じ `lineId` が新テンプレにもある** → ラベルだけ更新、数値は維持。
2. **消える行** → **`active: false` で非表示**（物理削除しない。過去データは `lineId` で維持）。
3. **増える行** → 空欄で追加。

初回は **確認ダイアログ必須**（「テンプレを変えると費目名が変わります」）。業態変更は稀だがゼロではないため、**完全に変更不可にはしない**。

### Monthly Edit 側の振る舞い

- 起動時に `plTemplateId` と **PL 行カタログ** を読み、`fixedItems` / `variableItems` の **ラベルと行構成の初期形** を同期。
- ユーザーが Edit で行を追加した場合: テンプレ外のカスタム行は `lineId: custom-*` として PL では「その他」に集約するか、PL にも動的行として反映するかは **第2段階**（v1 はテンプレ行＋少数カスタムまで）。

### KPI ラベル（食材原価率など）

- **行ごとのドロップダウン改名はしない**（計算とラベルの不整合を防ぐ）。
- テンプレ切替で **食材原価率 → 仕入原価率** など **一式で切り替え**。
