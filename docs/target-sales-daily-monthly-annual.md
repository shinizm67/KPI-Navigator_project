# Target Sales(Daily, Monthly, Annual)

## 1. 目的

`Area2` に表示・管理する `Target Sales` は、実績売上ではなく「目標売上額」を扱う。  
本メモは KPI Navigator のコアとなる目標売上算出ロジックの前提を整理する。

## 2. 基本前提

- `Target Sales` は `Daily / Monthly / Annual` の目標値。
- 実績売上は別管理とし、比較表示は `TW / Focus Bar / Graph` で行う。
- 当日営業中は実績が未確定のため、`Area2` の意味は「今日の目標はいくらか」を示すことに置く。

## 3. 算出フロー（高レベル）

1. 前年の全営業日に売上実績を入力する。
2. 前年の年次売上・月次売上・営業日数を確定する。
3. `前年年次売上 / 前年総営業日数` から 1日平均売上（基準値）を算出する。
4. 各月の `基準値 x 当月営業日数` で月次平均売上を算出する。
5. `実績月次売上` と `月次平均売上` の差分・比率から月次繁閑期パーセンテージを得る。
6. 今年の年次目標売上と営業日設定に、月次繁閑期パーセンテージを適用して月次目標を算出する。
7. 各月内では曜日別繁閑期パーセンテージを適用して日次目標を算出する。

## 4. 精度向上の考え方

- 繁閑期パーセンテージは前年のみでなく、前々年・さらに過去年を蓄積するほど精度向上が期待できる。
- 将来的には AI 解析を組み合わせ、同じ曜日でも日別に異なる目標額を提示できるようにする。

## 5. 制約・ガードレール

- 月次繁閑期設定・曜日繁閑期設定のいずれでも、最終合計は年次目標売上と一致させる必要がある。
- 年次目標を超過・不足しないよう、UI 上で誘導・補正支援を行う機能を必須要件とする。
- 曜日の出現回数差（例: 月曜が4回/5回）を考慮する必要がある。

## 6. UI/UX 方針（Area2）

- `Area2` は常に目標値を見せる領域とする（実績値は置かない）。
- 実績対目標の評価は `TW / Focus Bar / Graph` に集約する。
- これにより「今日の目標確認」と「実績比較分析」の役割分担を明確化する。

## 7. 実装メモ（将来）

- データモデル上で `target`（目標）と `actual`（実績）を分離する。
- 目標算出ロジックは再計算可能な形で保持し、履歴（いつ・誰が・何を変更）を残せる設計にする。
- 日次目標の再配分時は年次総額一致を必ず検証する。
