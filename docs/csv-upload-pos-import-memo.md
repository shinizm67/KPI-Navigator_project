# CSV アップロードによる入力簡略化（POS 前提）メモ

## フォント（プロダクト共通）

- **Sci-Fi モードかつ英語（`html[lang="en"]`）ページのみ**、本文フォントに **`Orbitron`** を用いる。
- **上記以外**（日本語ページ、Office モード、Sci-Fi の日本語ページなど）**すべて** **`BIZ UDPGothic`** に統一する。
- **例外として別のフォントファミリーを追加しない**（全体でこの 2 種類のみとする）

## プロダクト上の必須度（生命線）

- **CSV アップロードを起点とした「前年度・前営業日売上」などの取り込みはマスト機能**と位置づける。実装の「あれば便利」ではなく、**KPI Navigator の生命線**といっても過言ではないレベルで優先する。
- 来店型ビジネス（ターゲットの大半は **飲食店が多い想定**）では、正確な前年同日比・営業日ベースの比較に、このデータが直結する。

## ユーザー啓蒙（CSV とは何か）

- 技術以前の課題として、**CSV 形式のファイルが何を指すのか理解していない利用者が大多数**になると想定する（レジから「データを出す」こと自体に慣れていないケースも含む）。
- 機能を実装するだけでは足りず、**啓蒙・オンボーディング**をプロダクトに組み込む必要がある。例:
  - **言葉を噛み砕く**（「表計算ソフトで開ける文字のファイル」「レジのメーカーが案内するエクスポート」など）。
  - **POS ごとの「ここを押すと CSV が出ます」**の短いガイド・公式ヘルプへのリンク。
  - 初回フローでの **図解・動画・チェックリスト**（任意だが効果大）。
- 「CSV を知らない＝向いていない」ではなく、**こちらが導く設計**にしないとマスト機能が死ぬ。

## 位置づけ（技術・フロー）

- ユーザーの数値入力負荷を下げるため、**CSV アップロードで一括取り込み**する。上記のとおり **マスト**。
- ただし **「どの POS／レジシステムの CSV か」が分からないと**、列の意味や日付形式が特定できず、安全にパースできない。よって **POS 情報は CSV より先**（または同じ導線の最初のステップ）が必要。

## POS 情報をどこで聞くか

| タイミング | 狙い |
|------------|------|
| **Register** | 初回に聞ければ理想。登録フロー内で POS を確定しておくと、以降の CSV 取り込み UI が一貫する。 |
| **Register に載せない／後から変える場合** | ユーザーは **Register に再訪しない**ことが多い想定。→ **Settings の Profile（または同等の「アカウント・事業所情報」）** で POS を選択・変更できるようにするのが現実的。 |

**結論**: 可能なら Register で聞く。無理な場合や変更時は **Settings（Profile 等）で必ずどこかで聞ける**ようにする。

## ドロップダウンと「対応不可」の扱い

- UI は **ドロップダウンで対応 POS を列挙**し、ユーザーが自分のレジを選ぶ形が素直。
- リストに **ない場合は「対応不可」** とするしかない（汎用 CSV は列がバラバラで事故りやすい）。
- **難点**: 対応外のユーザーは **1 年分の売上などを手入力**してもらう必要があり、オンボーディングの摩擦が大きい。プロダクト上は
  - 対応 POS の拡充を継続する、
  - 手入力をできるだけ楽にする（テンプレ・月次まとめ入力など）、
  の両面でカバーする想定。

## 正しく意図通りに取り込めるかへの不安

- POS が分かっても、**店舗設定・エクスポートオプション・バージョン差**で CSV の形が変わる可能性がある。
- **心配は妥当**。対策の方向性としては例えば:
  - アップロード後の **プレビューと列マッピング確認**（可能なら）
  - **POS ごとの公式サンプル／ドキュメント**に基づくバリデーション
  - 最初は **少数 POS に絞って検証**し、フィードバックで拡張する

「とりあえずやってみる」前提で、**小さく出して学習する**のが現実的。

## ホバーツールチップ運用メモ（将来実装）

- 主要UI（特に CSV 取込、編集フロート、KPI 関連）は、段階的にホバーツールチップを追加する前提で設計する。
- 初期フェーズでは **意味補完の短文**（例: 「CSVファイルを取り込んで表を更新」）を表示する。
- 次フェーズで重要導線のツールチップに **YouTube チュートリアル URL** を持たせ、クリック時は **別タブ（`target="_blank"` + `rel="noopener noreferrer"`）** で開く。
- 文言は JP/EN で個別に管理し、動画URLもロケール別に差し替え可能な形（設定オブジェクト化）にする。
- ツールチップ本文は将来の動画導線を見越し、`description`（短文）と `helpUrl`（任意URL）を同時に扱えるデータ構造を推奨。
