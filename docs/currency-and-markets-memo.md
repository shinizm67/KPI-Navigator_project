# 通貨表示・市場展開メモ

## フォント（プロダクト共通）

- **Sci-Fi モードかつ英語（`html[lang="en"]`）ページのみ**、本文フォントに **`Orbitron`** を用いる。
- **上記以外**（日本語ページ、Office モード、Sci-Fi の日本語ページなど）**すべて** **`BIZ UDPGothic`** に統一する。
- **例外として別のフォントファミリーを追加しない**（全体でこの 2 種類のみとする）

## 通貨記号（¥ / $ など）とユーザー設定

- **方針**: Open 時に表示する年次ダッシュボードのテーブルやサマリーに出す通貨マーク（`¥`、`$` など）は、**初期登録（Register）でユーザーが選んだ国・地域、およびそれに紐づく Currency 設定**と一致させる。
- **現状**: 年次ページ等では開発用の固定表示（例: EN で `$`、JP で `¥`）になっている箇所がある。本番では **登録時に保存した通貨コード／ロケール**からフォーマットを決定し、ページ言語と必ずしも同一である必要はない（ユーザー設定が優先）。
- **実装時の確認ポイント**:
  - 登録フローで保持するフィールド: 国・地域、通貨（ISO 4217 など）。
  - 表示層: `Intl.NumberFormat` や共通の `formatCurrency(amount, userCurrency)` のような単一のヘルパに集約する。
  - テーブル・KPI ストリップ・モーダルなど、金額を出すすべての UI で同じソースを参照する。

## Stripe 展開とサブスク提供可否の判断

- **前提**: Stripe で「販売できる地域」と「自社がトラブルシュート・サポートを十分に回せる地域」は一致しない。サブスクリプションをその国・地域で提供するかは、**技術的可否だけでなくサポート体制・コンプライアンス・その他リスク**を一覧にして判断する想定。
- **検討の進め方（案）**: 国・地域ごとにテーブル化し、Stripe 対応、税・請求書、言語、サポートタイムゾーン、既知リスクなどを並べて Go / No-Go を決める。
