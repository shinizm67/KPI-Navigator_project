## 発端（2026-07-17 の議論）

L2 参考予算を「前年以前のデータがある時だけ」出す方針に確定（[pl-table-v1-implementation-spec.md](./pl-table-v1-implementation-spec.md)）。
これを踏まえ「過去の支出データをどう入れてもらうか」が現実の課題として浮上。売上は既に CSV/Excel 取り込みがあるが、**支出も CSV/Excel で入れたい**という要望。

さらに一歩踏み込んだ狙い（ユーザー発）:

> **最終的に PL の費目名は、Excel / CSV から取り込んだものを最優先（source of truth）にしたい。**

つまり支出取り込みは「金額を入れる」だけでなく、**費目カタログそのものをユーザーの Excel 由来で構築する**方向に効いてくる。

---

## なぜ売上より難しいのか（difficulty の本体）

**難しさはパース（読み取り）ではなく「費目名のマッピング」にある。**

| | 売上 | 支出 |
|---|------|------|
| データの形 | 「日付 → 1 つの金額」 | 「日付 / 月 → **費目ごと**に複数金額」 |
| 必要な列 | 日付・売上 | 日付・**費目名**・金額（または費目が横に何列も並ぶ） |
| 追加で必要な処理 | ほぼ無し（既存 `__KPI_DAILY_IMPORT` で完結） | CSV の費目名を、アプリ側の**可変な費目カタログにマッピング**する仕組み |

→ **「あらゆる店の Excel を自動で完璧に読む」は目指さない**（沼）。

---

## 粒度：日次 vs 月次（最初に決める）

店の実務に合わせ、**両方受ける**設計が必須。

| 費目例 | 実務の付け方 | 取り込み粒度 |
|--------|--------------|--------------|
| 食材費・ドリンク費・小口 | **日次**で付けている店が多い | 日次（`date, item, amount` 長形式 or 費目横並び） |
| アルバイト人件費 | 月次が多い（**日次化は提案ポイント**） | 月次（`month, item, amount`） |
| 家賃・光熱・保険・システム料 等 | 月次請求書ベース | 月次 |

- 既存の入力元設計（[pl-expense-input-source-design.md](./pl-expense-input-source-design.md)）の Daily/Monthly と整合させる。
- 取り込んだ粒度が、その費目の `inputStyle`（daily/monthly）と矛盾しないようにする（または取り込み時に確定）。

## 採用したい方針：二段構えのハイブリッド

「こちらで雛形を作って DL させる」は**乱暴ではなく SaaS の王道**（freee / マネフォ 等）。
クリーンなデータ＝**根拠を問われても説明できる**（L2 で確定した「信じられるデータしか出さない」思想と一致）。
一方で「各店に既存の Excel 雛形がある」現実も無視できない。→ 両立させる。

### ① 推奨ルート：雛形（テンプレート）DL → 記入 → Upload
- こちらが定義したフォーマットを DL してもらう（迷わない・確実・サポートコスト最小）。
- **golden path**。オンボーディングの基本導線。

### ② 自由ルート：店の既存 Excel を Upload → 列マッピング画面
- アップロード後、**検出した列を提示し「この列＝食材費」を人が 1 回だけ指定**（以後は記憶）。
- 「機械が全部当てる」無理ゲーを回避しつつ、店の既存ファイルを受け入れられる。
- **この列マッピングの瞬間に、費目名を費目カタログへ登録** → 狙い「費目名は Excel 取り込みが最優先」を自然に実現。

### 篩（ふるい）の原則
**Upload → 列を検出 → マッピングできれば通す / できなければ明確に弾いて雛形へ誘導。**
全部を自動で飲み込もうとしない。売上 POS メモの「対応不可なら弾く」思想と同じ。

## 費目カタログとの関係（source of truth 問題）

- 現状: **PL 表が科目マスタの正**（`kpiNavigator.plLineCatalog`。詳細は入力元設計 doc）。
- 狙い: **Excel 取り込みの費目名を最優先**にしたい。
- 論点（未決）:
  - 取り込み時、既存カタログと**名寄せ**するか（表記ゆれ・別名辞書）。
  - 取り込みで**新規費目を自動追加**するか、マッピング画面で**既存費目に割り当て**させるか。
  - `sortOrder` / `bucket`（固定/変動）/ `inputStyle` を取り込み時にどう決めるか。
  - ソフト削除（`active:false`）済み費目と衝突した場合の扱い。

> 現時点の仮結論: **マッピング画面で「既存へ割当 or 新規作成」を選ばせる**。自動全上書きはしない（既存データ整合を壊さないため）。

## 既存資産の流用

`scripts/daily_sales_import_client.py` の `window.__KPI_DAILY_IMPORT` に、支出でもそのまま使える部品が揃っている:

- CSV / TSV / `;` 区切りの**区切り文字自動検出**（`detectDelimiter` / `splitCsvLine`）
- **Excel(.xlsx/.xls) 対応**（xlsx CDN 遅延ロード → `sheet_to_json`）
- **日付セルの正規化**（ISO / Excel シリアル値 / `new Date` フォールバック）
- 金額セルの正規化（`¥ $ , 空白` 除去）
- ファイル選択 input・確認ダイアログ・年フィルタの導線

→ **新規に必要なのは「列マッピング（費目 ↔ 列）」層と、月次/日次の書込先分岐**（`kpi-pl-expenses-v1:{year}` と `kpiYearStore.years.{Y}.dailyExpenses`）。

## 雛形フォーマット確定（2026-07-17）— 縦形（long）統一

**日次・月次とも「縦形（long）」に統一。** 取り込みロジックを1本化でき、費目マッピングも共通化できるため堅牢。

### 列定義（3列）

| 列名（JA / EN） | 内容 | 例 |
|---|---|---|
| `日付` / `date` | **日次**は `YYYY-MM-DD`、**月次**は `YYYY-MM`。値の形で粒度を自動判定 | `2025-01-05` / `2025-01` |
| `費目` / `item` | 費目名（カタログへマッピング or 新規作成） | `食材費` |
| `金額` / `amount` | 整数（円）。`¥ , 空白` は除去して解釈 | `42000` |

- **1ファイルは基本1粒度**（日次のみ or 月次のみ）を推奨。行ごとに粒度混在も技術上は許容するが、**同一費目を日次と月次の両方で入れない**（二重計上防止・[pl-expense-input-source-design.md](./pl-expense-input-source-design.md) の入力元1本化と整合）。
- 将来の任意列候補: `メモ`（`memo`）、月跨ぎ用 `対象月`（`target_month`）。初期は3列のみ。

### サンプル雛形ファイル（`excel/`）

| ファイル | 用途 |
|---|---|
| `excel/支出入力_日次_雛形.csv` | 日次（食材費・ドリンク費・小口 等） |
| `excel/支出入力_月次_雛形.csv` | 月次（アルバイト費・家賃・光熱費 等） |
| `excel/expense-import_daily_template.csv` | EN daily |
| `excel/expense-import_monthly_template.csv` | EN monthly |

> フェーズ2 でこれらを DL 導線（PL / MEP の「雛形をダウンロード」）から配布する。現状はフォーマット定義＋サンプルのみ（取り込み実装は未着手）。

## MEP の CSV アップロード現状調査（2026-07-17）

対象: `app/monthly/edit/index.html`（および `en/app/monthly/edit/index.html`）。ボタン ID `monthly-edit-float-csv-upload`。

### 分かったこと（＝既に動いている）

- MEP の CSV アップロードは **スタブではなく完動**。売上と同じエンジン `window.__KPI_DAILY_IMPORT` に接続済み（CSV/TSV/`.xlsx`・区切り/日付自動検出を共通利用）。
- 取り込み先は **`state.incomeItems[0]`（＝ Store Sales / 収入）**。現状は**収入専用**。
- **年単位で反映**：`applyDailyImportMapsToOpenYear(maps, year)` が、開いている月だけでなく **その年（`mefYear`）の全日付**に反映 → `syncMonthlySalesToAnnualStoreForYear(mefYear)` で annual 共有ストアへ同期。
  - → **Sales Data と同じ挙動**（年次 CSV を入れても各月の Store Sales に分配される）。「MEP からでも Sales Data からでも同じ共有ストアに着地」＝ Pro の「どちらからでも入力」を既に満たす。
- 仕様の明確化：CSV に複数年が含まれても **開いている年のみ**反映（Sales Data と同じ年フィルタ）。書込は `KpiYearStore.canWriteDailySalesFrom('mep', iso)` のガードを通る。

> 結論：**「MEP で CSV UL 可能・収入は Sales Data と同挙動で完成済み」**。この点は追加実装不要。

| ② | **支出**の取り込み本体（費目マッピング・日次/月次） | **未実装**（本メモ本体の領域） |

## 実装状況（2026-07-17 スライス1：PL 支出取込 本体）

**PL ページ（`app/profit/pl/index.html` / `en/...`）の「Upload CSV」を本物にした。** これまでは「準備中」アラートのスタブ。

- 新規クライアント `scripts/pl_expense_import_client.py`（`pl_expense_import_client_js`）を追加し、`scripts/build_pl_table_page.py` の PL ツールバー IIFE 内に埋込（`plYear` / `formatMoney` / `pad2` / `btnCsv` をクロージャ共有、他クライアントとは `window.__pl*` 経由で連携）。
- **導線（役割分担、2026-07-18 決定）**：当初は収入/支出チューザーを実装したが、UX 検討の結果**「PL＝支出 / MEP＝売上(収入)」の役割分担**に確定。チューザーは廃止し、PL の Upload ボタンは**押下で即・支出ファイル選択**。ボタン名も明示化（PL＝「支出CSV取込 / Upload Expenses」）。収入（日次売上）は Monthly Edit / Annual Sales Data 側の役割。
- **雛形一致ルート**（メモ #4）：縦形 `日付/費目/金額` を CSV/TSV/`.xlsx`（xlsx は CDN 遅延ロード）で読取。列はヘッダー語（日付/費目/金額・date/item/amount）で自動検出、無ければ位置（0/1/2）フォールバック。
- **費目マッピング**：費目名を `kpiNavigator.plLineCatalog` の `labelJa`/`labelEn`/`lineId` に**正規化（空白除去・小文字化）した完全一致**で対応付け。**未一致はスキップして明示**（「篩」原則）。列マッピングUI・費目自動作成は次スライス。
- **粒度判定と書込先**：`YYYY-MM-DD`＝日次 / `YYYY-MM`＝月次。
  - 月次スタイル費目 → `kpi-pl-expenses-v1:{year}`（`"{lineId}:{month0}"`、既存値は取込分のみ上書き）。適用後 `window.__plWriteMonthlyExpenseAllocationToMep({year})` で MEP 日割りへ伝播（＝Save と同挙動）。
  - 日次スタイル費目 → `kpiYearStore.years.{Y}.dailyExpenses[lineId][iso]`（ゲートウェイ経由）。日次スタイル費目に月次データが来た行は「粒度不一致」でスキップ・報告。
- **複数年対応**：ファイル内の全年に書込。表示中の年（`plYear`）に該当分は即再描画、他年は年セレクタ切替で反映（確認ダイアログに明記）。取込前に `window.confirm` で件数・一致/未一致・対象年のサマリを提示。
- 検証：Chrome ヘッドレスのハーネスで実カタログ×実雛形4ファイルの parse→map→plan→write を確認（全行一致・日次/月次振り分け・未一致スキップ・localStorage 書込を確認）。PL 日英ページとも読込時 JS エラー無し。チューザーのレンダリングも確認。

### 併せて修正：雛形CSVの費目名をカタログ正式ラベルへ整合
取込は**費目名がカタログのラベルと完全一致する必要がある**。旧雛形は口語名（食材費 / ドリンク費 / 小口 / アルバイト費）でカタログ（食材仕入れ費 / ドリンク仕入れ費 / …）と不一致だったため、`excel/` の4ファイルを**カタログ正式ラベル・正しい粒度**へ更新（日次＝食材仕入れ費・ドリンク仕入れ費・アルバイト人件費／月次＝家賃・固定人件費・電気代・ガス代・水道代・損害保険・通信費 等）。雛形＝クリーンデータの担保に必須。

### 重要な訂正（現状調査で判明）
本メモ §MEP調査で「MEP の CSV アップロードは完動」と記したが、**実際には取込エンジン `window.__KPI_DAILY_IMPORT` は現在 annual ページにしか注入されておらず、MEP / PL の生成HTMLには未ロード**（`scripts/apply_daily_sales_import.py` の再注入対象・生成タイミングのズレ）。PL 支出取込は本スライスで**エンジンに依存しない自己完結パーサ**を新規実装したため影響なし。MEP 側の収入取込を有効化するには、エンジンの再注入（または共通化）が別途必要。
