## 1) いま何が画面にあるか（2026-08-18）

**2026-08-18 マイナー更新:** PL 表ツールバーの売上入力インジケータ（`.kpi-daily-input-path--pl-readonly`）は **UI から非表示**。HTML / CSS / JS は残し、後で復活可能（[§8](#8-pl-売上入力インジケータの非表示と復活手順)）。

非表示前の仕様（メモ）:

PL 表ツールバーのスイッチ風 UI は **切替できない表示**であった。

| 項目 | 事実 |
|------|------|
| 意味 | 日次**売上**を、年次側と月次編集側のどちらで入力しているかの表示 |
| 操作 | 押せない。切替は月次編集ページまたは年次の売上画面 |
| PL の売上 | PL では売上を入力しない（表示のみ） |
| PL の支出 | この表示とは無関係に編集できる（仕様） |

見出しが「編集」だった時期があり、Past Sales の **閲覧／編集** と間違えやすい。日本語ラベルを年次／月次にし、見出しを「売上入力」、ツールチップを「表示のみ」にしたあとも、**スイッチに見えるのに支出が編集できる**違和感は残る。

docs 上の位置づけは Option A（インジケータ）。編集ロックではない。

---

## 2) なぜ困っているか

支出は一度いじると影響が大きい。  
「特定の人だけが編集し、アルバイトは見るだけ」にしたい。

一方で:

- 毎回パスワードを求めると現場が嫌がる
- 「トグルの存在を編集者にだけ教える」運用は、画面に閲覧／編集と書いてある時点で見つかる
- トグルを知っていること ≠ 権限。PL を開ける人は倒せる

いまの年次／月次表示は、この問題を解いていない。置く意味が薄く、混乱の元になっている。

---

## 3) トグルで守れるもの／守れないもの

| 目的 | トグルだけで足りるか |
|------|----------------------|
| うっかり上書きを減らす | **足りる**（デフォルト閲覧、編集に倒してから入力。Past Sales と同じ） |
| 特定の人だけ編集させる | **足りない**。ログインした人の役割が必要 |
| 教えないことで守る | **足りない**。秘密のトグルにはならない |

結論の芯: トグルは **鍵ではなく安全装置**。鍵はアカウント（誰で入ったか）側。

## 7) 提案案: Personal＝トグルなし / Team＝役割＋編集者のみトグル＋閲覧者の一時昇格

**ステータス: 提案（未決）** — 2026-08-18 議論で方向性として記録。本番仕様ではない。

### 概要

| Workspace | 編集権限 UI | 備考 |
|-----------|-------------|------|
| **Personal** | **トグルなし** | オーナーはそのまま編集可。うっかり防止より操作の軽さを優先 |
| **Team** | **役割で分岐** | サーバー側で閲覧者／編集者を強制。UI は役割に応じて出し分け |

Team では **トグルは鍵ではなく安全装置**（§3）。鍵は「誰でログインしたか＋役割」。

### Personal（個人）

- 想定: 店長など、ほぼ 1 アカウントで運用
- **閲覧／編集トグルは置かない** — 毎回切り替える手間・「編集できない」誤解を避ける
- PL の **売上入力インジケータ（年次／月次・表示のみ）も Personal では非表示** にする案（Team 専用 UI と混同しないため）
- 同じログインを 2 人以上で共有するリスク: トグルでは防げない。設定・招待時に「共有アカウントのリスク」を注意喚起する側（§5 の未決事項）

### Team（チーム）

人ごとにログインが分かれる前提。**役割が先、トグルは編集者向けの追加レイヤー**。

#### 役割

| 役割 | 通常の PL 支出 | トグル UI |
|------|----------------|-----------|
| **閲覧者（Viewer）** | 常に読み取り専用 | **出さない**（教えなくても触れない） |
| **編集者（Editor）** | 編集可（トグル状態に依存） | **閲覧／編集** を表示（Past Sales と同型の誤操作防止） |

- 閲覧者にトグルを出さない → 「秘密のトグル」運用に頼らない
- 編集者だけデフォルト **閲覧** → 意図して **編集** に倒してから入力

#### 閲覧者の一時昇格（例外編集）

閲覧者がたまに数字を直す必要がある場合:

1. **v1: ワンタイムパスワード（OTP）** — 編集者またはオーナーが発行。短時間・限定回数の編集権限
2. **後追い: 編集者への許諾リクエスト** — アプリ内で承認フロー。OTP より運用負荷は高いが監査しやすい

どちらも **サーバー側で昇格状態を検証** する（クライアントのトグルだけでは不可）。

#### PL 上の UI 整理（Team 向け・将来）

- いまの **売上入力パス表示（年次／月次・読み取り専用）** は PL では混乱の元 → Team では **Past Sales 型の閲覧／編集** に差し替える案（未決・§5）
- 売上入力パスの切替は引き続き **月次編集ページまたは年次の売上画面** で行う（PL では切替しない）

### 実装フェーズ（提案順・すべて未着手）

| フェーズ | 内容 | 備考 |
|----------|------|------|
| **1** | Workspace 種別（Personal / Team）のデータモデルと判定 | 現状はヘッダ表示のみ |
| **2** | ユーザーごとの役割（Viewer / Editor）を **サーバーで強制** | API・保存時チェック含む |
| **3** | 編集者のみ **閲覧／編集トグル**（任意の安全装置） | Past Sales パターン流用可 |
| **4** | 閲覧者の **一時昇格** — まず OTP、のち許諾リクエスト | v1 / v2 で分割 |

フェーズ 1–2 が無い状態でトグルや OTP だけ足しても、共有ログイン問題は解けない（§3・§6）。

### この提案で意図的にやらないこと

- Personal に「念のため」トグルを付ける — 操作コストと混乱を増やすだけ、という判断
- 閲覧者にもトグルを見せて「編集に倒せば触れる」 — 権限モデルと矛盾
- PL の売上入力インジケータを、Team の編集ロックと混同させ続ける — Team 移行時に差し替え／非表示を検討

### 関連画面への波及（メモのみ・未決）

- **Past Sales** — 既存の閲覧／編集トグルは Team 編集者向け安全装置の参考実装
- **MEP / 月次編集** — Team 役割が入ったら、CSV アップロード・セル編集もサーバー側で Viewer をブロックする必要あり（別途設計）
- **売上入力パストグル** — 権限とは別軸（どこで日次売上を入れるか）。混同しない（[daily-input-path-toggle-tonmana-memo.md](./daily-input-path-toggle-tonmana-memo.md)）

## 8) PL 売上入力インジケータの非表示と復活手順

**決定（2026-08-18）:** PL の年次／月次表示（売上入力パス・読み取り専用）は **一旦不要**。UX 優先でツールバーから外す。Team 権限や Past Sales 型トグルは **別途・後日**（§7）。

### いまの状態

| 項目 | 内容 |
|------|------|
| 画面 | 3 言語 PL（`app/profit/pl/`、`en/`、`zh-tw/`）で **表示しない** |
| コード | HTML ブロック・CSS（`.kpi-daily-input-path--pl-readonly`）・JS（`/* PL-SALES-INPUT-PATH-INDICATOR */`）は **削除せず残す** |
| フラグ | 各 HTML の IIFE 内 `PL_SALES_INPUT_PATH_INDICATOR_ENABLED = false` |
| 正本スクリプト | `scripts/pl_sales_input_path_indicator_client.py` の `PL_SALES_INPUT_PATH_INDICATOR_ENABLED = False` |
| 目印 | HTML に `data-pl-sales-path-indicator-disabled="1"` とコメント |

### 復活手順（Team 向け UI 等で再表示するとき）

1. `scripts/pl_sales_input_path_indicator_client.py` で `PL_SALES_INPUT_PATH_INDICATOR_ENABLED = True` に変更
2. 3 つの PL `index.html` で `PL_SALES_INPUT_PATH_INDICATOR_ENABLED = true` に変更（`/* PL-SALES-INPUT-PATH-INDICATOR */` ブロック内）
3. （任意）HTML コメントと `data-pl-sales-path-indicator-disabled` を削除
4. `build_pl_table_page.py` から PL を再生成する運用なら、手順 1 のあと rebuild で 2–3 が追随するか確認
5. Pro 契約時のみ表示・`kpi:dailySalesInputPathChanged` で同期 — 旧挙動はスクリプト内にそのまま残っている
